# 04. フィードバックの回し方

**目的: 「なんとなく駄目だった」を「どこで落ちたか」に変える。**

反省文は書かない。**落ちた場所を1語で残すだけ。**溜まれば、次に直す場所が推測ではなく事実で決まる。

---

## A. 落ちる場所は5つしかない

| # | 落ちた場所 | 直す先 |
|---|---|---|
| **1** | 受付で切られた | `02` C / C-2 / D |
| **2** | 担当者が不在のまま終わった(名前も取れず) | `02` D の不在枝 |
| **3** | 担当者に、用件を聞く前に断られた | `02` E(矛盾)/ `03` 冒頭 |
| **4** | 懸念・断りが出たが、**返せずに終わった** | `03` に**その枝が無い** |
| **5** | 返したが、**決まらなかった** | `03` の**返しの中身が弱い** |

### ⚠️ 4 と 5 の区別が最重要

ここを混ぜると、**直っているのに直っていないと思い込む**(逆もある)。

- **4 = 弾が無かった。** → 枝を追加すれば解決。**追加した時点で終わり**
- **5 = 弾はあったが効かなかった。** → 中身を作り直す必要がある。**まだ何も解決していない**

**毎回どちらだったかを必ず書く。**

---

## B. 記録フォーマット

1コール1行。長く書かない。**30秒で書けなければ続かない。**

```
日付 / 会社名 / 業種
落ちた場所: [1受付 / 2不在 / 3即断り / 4返せず / 5返したが駄目]
相手の言葉(そのまま): 「________________」
自分が返したこと: 「________________」(返していなければ「なし」)
次にやること:
```

### 日次の集計(1行)

```
日付 / コール数 / 受付突破数 / 担当者接触数 / アポ数
```

### 💡 MiiTel が使えるなら

| 見る数字 | 何が分かるか |
|---|---|
| **通話時間の分布** | 受付で切られたコールは極端に短い。1 の件数が推定できる |
| **トーク:リッスン比率** | `03` の質問型が機能していれば**相手の発話が増えるはず** |
| **話速** | `02` C 案「早口にしない」の検証 |
| **沈黙 / 被り** | `02` C 案「一拍置く」の検証 |

**特にトーク:リッスン比率。**「質問型に変えた」が効いているかを感覚ではなく数字で言える。

---

## C. 週次でやること(15分)

1. 落ちた場所を **1〜5 で集計**する
2. **一番多い番号だけ**を直す。2つ以上同時に直さない
3. 4 が出ていたら → `03` に枝を追加する
4. 5 が出ていたら → その枝の**❷聞く**と**❹確認する**を作り直す

### ⚠️ 検証は一度に1つだけ

`02` F のとおり。同時に複数変えると、何が効いたか永久に分からなくなる。

| 週 | 変えるもの |
|---|---|
| 1週目 | **現状のまま計測(基準値を取る)** |
| 2週目以降 | 一番多い落ち方に対して、1つだけ変える |

---

## D. 実例ログ

### #001 2026-08-19 — 「Indeedしか取っていない」

| | |
|---|---|
| 落ちた場所 | **4(返せずに終わった)** ✅確定 |
| 受付 | **「お取次ぎお願いいたします」で突破** ← `02` 案A の言い回し |
| 担当者の言葉 | 「Indeedしか取っていない」 |
| 自分が返したこと | **相手の言葉を復唱しただけ**(質問に進まず終話) |
| 対応 | `03` に **6.「Indeedしか取っていない」** を新規追加 |

**分かったこと**
- **`02` の受付トークが実戦で通った。** ただし **n=1 なので突破率については何も言えない。**
  「この言い方が受付に嫌われて即切られる」ことは無い、が確認できた段階
- **`03` に「既存の手段があるから要らない」系の断りが丸ごと無かった** → 追加済み

**判定: 4(弾が無かった)。5(弾が効かなかった)ではない。**
→ **`03` に6番を追加した時点で対応済み。**返しの中身を見直す必要はない。

**もう1つ分かったこと ── 復唱で止まっている**
- 復唱は `03` の**❶受ける、そのもの。**型の1/4はできていた
- **止まったのは❷に進まなかったから。**これは6番だけの問題ではなく**全ブロックで起きうる**
- → `03` の共通の型に **「❶と❷の間に必ず『ちなみに』を入れる」** を追加した

---

## E. 前提の扱いについて

**「受付が一番落ちている」は本人の感覚値であって、まだ数字ではない。**
#001 で受付を突破しているが、**1件通ったからといって前提は覆らない。**

→ **受付突破率と、担当者接触後のアポ率の両方**を測る。
どちらが本当のボトルネックかは、基準値を取ってから判断する。
