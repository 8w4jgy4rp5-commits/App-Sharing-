# 04. フィードバックの回し方

**目的: 「なんとなく駄目だった」を「どこで落ちたか」に変える。**

反省文は書かない。**落ちた場所を1語で残すだけ。**溜まれば、次に直す場所が推測ではなく事実で決まる。

---

## A. 落ちる場所は5つしかない

| # | 落ちた場所 | 直す先 |
|---|---|---|
| **1** | 受付で切られた | `02` C / C-2 / D |
| **2** | 担当者が不在のまま終わった(名前も取れず) | `02` D の不在枝 |
| **3** | 担当者に、用件を聞く前に断られた | `02` E(矛盾)/ `03` 冒頭 |
| **4** | 懸念・断りが出たが、**返せずに終わった** | `03` に**その枝が無い** |
| **5** | 返したが、**決まらなかった** | `03` の**返しの中身が弱い** |

### ⚠️ 4 と 5 の区別が最重要

ここを混ぜると、**直っているのに直っていないと思い込む**(逆もある)。

- **4 = 弾が無かった。** → 枝を追加すれば解決。**追加した時点で終わり**
- **5 = 弾はあったが効かなかった。** → 中身を作り直す必要がある。**まだ何も解決していない**

**毎回どちらだったかを必ず書く。**

---

## B. 記録フォーマット

1コール1行。長く書かない。**30秒で書けなければ続かない。**

```
日付 / 時刻 / 会社名 / 業種
落ちた場所: [1受付 / 2不在 / 3即断り / 4返せず / 5返したが駄目]
相手の言葉(そのまま): 「________________」
自分が返したこと: 「________________」(返していなければ「なし」)
2の場合に取れたもの: [戻り時間 / 部署 / 名前 / 何も取れず]
次にやること:
```

### ⚠️ 2(不在)が多いときは、時刻を必ず書く

**「だいたい不在」は時間帯のせいかもしれない。**
時刻を記録していれば、1週間で「何時にかけると不在が多いか」が分かる。
**推測で時間帯を変えない。**(→ `02` D-2)

### 日次の集計(1行)

```
日付 / コール数 / 受付突破数 / 担当者接触数 / アポ数
```

### 💡 MiiTel が使えるなら

| 見る数字 | 何が分かるか |
|---|---|
| **通話時間の分布** | 受付で切られたコールは極端に短い。1 の件数が推定できる |
| **トーク:リッスン比率** | `03` の質問型が機能していれば**相手の発話が増えるはず** |
| **話速** | `02` C 案「早口にしない」の検証 |
| **沈黙 / 被り** | `02` C 案「一拍置く」の検証 |

**特にトーク:リッスン比率。**「質問型に変えた」が効いているかを感覚ではなく数字で言える。

---

## C. 週次でやること(15分)

1. 落ちた場所を **1〜5 で集計**する
2. **一番多い番号だけ**を直す。2つ以上同時に直さない
3. 4 が出ていたら → `03` に枝を追加する
4. 5 が出ていたら → その枝の**❷聞く**と**❹確認する**を作り直す

### ⚠️ 検証は一度に1つだけ

`02` F のとおり。同時に複数変えると、何が効いたか永久に分からなくなる。

| 週 | 変えるもの |
|---|---|
| 1週目 | **現状のまま計測(基準値を取る)** |
| 2週目以降 | 一番多い落ち方に対して、1つだけ変える |

## D. 実例ログ

### #001 2026-08-19 — 「Indeedしか取っていない」

| | |
|---|---|
| 落ちた場所 | **4(返せずに終わった)** ✅確定 |
| 受付 | **「お取次ぎお願いいたします」で突破** ← `02` 案A の言い回し |
| 担当者の言葉 | 「Indeedしか取っていない」 |
| 自分が返したこと | **相手の言葉を復唱しただけ**(質問に進まず終話) |
| 対応 | `03` に **6.「Indeedしか取っていない」** を新規追加 |

**分かったこと**
- **`02` の受付トークが実戦で通った。** ただし **n=1 なので突破率については何も言えない。**
  「この言い方が受付に嫌われて即切られる」ことは無い、が確認できた段階
- **`03` に「既存の手段があるから要らない」系の断りが丸ごと無かった** → 追加済み

**判定: 4(弾が無かった)。5(弾が効かなかった)ではない。**
→ **`03` に6番を追加した時点で対応済み。**返しの中身を見直す必要はない。

**もう1つ分かったこと ── 復唱で止まっている**
- 復唱は `03` の**❶受ける、そのもの。**型の1/4はできていた
- **止まったのは❷に進まなかったから。**これは6番だけの問題ではなく**全ブロックで起きうる**
- → `03` の共通の型に **「❶と❷の間に必ず『ちなみに』を入れる」** を追加した

---

### #002 2026-08-19 ドリームホールディングス(物流・三重)— **✅ 訪問アポ獲得**

| | |
|---|---|
| 落ちた場所 | **なし(アポ獲得)** |
| 受付 | **グループ会社ルート**で突破(→ `02` 案E) |
| 担当者 | 田中様 |
| 相手の状況 | **採用している。** ドライバーを探している |
| 相手の質問 | ①ドライバー経験者はいるか ②会社はどこか ③三重に永住者はいるか ④**永住権のみか** |
| 相手の条件 | **「東京からこっち来てくれるんやったら話聞きますけど」** |
| 対応 | その場で断らず持ち帰り → **京都の担当者が訪問できることが判明** → 折り返してアポ |
| 結果 | **訪問決定。日程は未確定(後日メールで調整)** |

#### 効いたこと(再現する)

1. **グループ会社ルート** —「別の番号にかけたらこちらだと言われた」は**検証可能な具体的理由**。
   営業ではなく事務連絡に聞こえる → `02` 案E として追加
2. **相手の条件を否定せず、持ち帰って満たした** ← **本当の勝因。**
   自分の裁量で「東京なので難しい」と答えていたら死んでいた → `03` に追加
3. **名前を取っていた** — これが無ければ折り返せなかった(`02` D-2 が機能)

#### 直すこと

| # | 問題 | 対応 |
|---|---|---|
| 1 | **相手の4つの質問に、全部説明で返した** | → `03` 失敗パターン2 として追加 |
| 2 | ②冒頭が改訂版になっていない(「ですねー」「あのー」が全部戻っている) | `03` 0 を見ながら話す |
| 3 | **登録者数を「50万」→「47万」と言い直した** | `01` の要確認事項。**社内資料で1つに確定させる** |
| 4 | 「昔ドライバーの免許を持っていた人が非常に多い」**根拠不明** | 商談で崩れる。要確認 |
| 5 | 断言を避けようとして文が壊れた | 短く言い切る |
| 6 | 自社を「御社」と言った | — |
| 7 | 名乗りで約1分消費(名前が5回聞き返された) | 受付では**会社名を主に** |
| 8 | **その場で仮日程を押さえなかった** | → `03` に追加 |

#### ⚠️ 未完了リスク(最重要)

**日程が未確定のまま「後日メールで」になっている。**

- **相手のアクション待ちは危険。**待っていてもメールは来ない
- **行くのが京都の別担当者。**引き継ぎの間に熱が冷める

→ **こちらから当日中にメールを送り、日程の候補を2〜3出す。**
→ **電話で聞いた内容(ドライバーを探している)を訪問担当者に必ず引き継ぐ。**

#### 商談前の準備

田中様の **「永住権のみですか?」** は、商談で深掘りされる可能性が高い。
**物流業界は特定技能でもドライバーを採用できる**(自動車運送業が対象。要件は社内で確認)。
→ 「なぜ永住権だけなのか」と聞かれる前提で、`01-facts.md` B の比較表を用意する。
**「永住権のみ」は制約ではなく、手続きの軽さという強み。**

## E. 前提の扱いについて

**「受付が一番落ちている」は本人の感覚値であって、まだ数字ではない。**
#001 で受付を突破しているが、**1件通ったからといって前提は覆らない。**

→ **受付突破率と、担当者接触後のアポ率の両方**を測る。
どちらが本当のボトルネックかは、基準値を取ってから判断する。
